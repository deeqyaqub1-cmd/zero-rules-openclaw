THE PROBLEM

Multi-agent coordination is held together
with markdown files

❌ Before (DECISIONS.md)
# DECISIONS.md (append-only) - 2026-02-15: Use Clerk for auth - 2026-02-16: Tests block deploy # "What blocks deploy?" # → grep returns text blobs
✔ After (HyperStack)
const result = await hs.blockers("deploy-prod"); // → [migration-23] Auth migration // blocks → deploy-prod // → [staging-tests] 3 tests failing // blocks → deploy-prod

Typed relations. task→blocks→deploy is queryable. Markdown is not.

Fork your memory workspace, experiment freely, then merge or discard. Branch before risky agent actions. Diff shows exactly what changed. Parent graph always untouched. Requires Pro+.

🔍

4 Graph Modes. One Parameter.

Forward traversal, impact analysis, co-citation recommendations, and time-travel. Neo4j needs Cypher queries for each. HyperStack: one parameter change.

// Forward — what does this connect to? await hs.graph("auth-api", { depth: 2 }); // Impact — what breaks if this changes? await hs.impact("use-clerk"); // Recommend — what's related? await hs.recommend("deploy-prod"); // Time-travel — what did we know then? await hs.graph("auth-api", { at: "2026-02-01" });

CORE CONCEPT

🃏 What are Cards?

Cards are small, structured chunks of knowledge your agent stores and retrieves. Think of them as index cards for an AI brain. Each card has:

slug

Unique ID — same slug = update, not duplicate

title

Human-readable name for the card

keywords

Tags for exact-match search

stack

Category folder (projects, people, etc)

cardType

person, project, decision, preference, workflow, event, account

links

Connect cards by slug — build a knowledge graph
